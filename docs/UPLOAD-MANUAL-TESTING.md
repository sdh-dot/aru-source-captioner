# 업로드·출처 매칭 수동 검증

대상 개발본은 Firefox 1.0.4 / Whale·Chromium 0.1.3이다. 기존 스토어 제출본을
자동 교체하지 않는다. 작성 중인 글을 먼저 별도로 보존하고, 별도 테스트
프로필이나 비어 있는 테스트 작성기에서 검증한다. 실제 등록/수정 완료
버튼은 누르지 않는다.

## Android Firefox

사용자가 보고한 환경은 마켓 버전 1.0.3,
`https://m.ruliweb.com/community/board/300143/write`이다. 저장소 main의
Manifest는 검사 시점에 0.1.2였다. 버전 숫자를 임의로 동일한 것으로
취급하지 않고 새 Firefox 번호는 사용자가 확정한 1.0.4를 사용했다.

1. 새 개발본을 시험할 수 있는 Firefox 환경에서 위 작성 화면을 연다.
   일반 모바일 Firefox에서 임의 ZIP을 설치할 수 있다고 가정하지 않는다.
   AMO 시험 배포/서명 절차가 필요하면 소유자가 별도로 진행한다.
2. 출처가 서로 다른 시험용 이미지 3개를 준비한다. 개인 이미지와 인증정보를
   포함한 파일을 쓰지 않는다. 파일명 출처 이미지와 메타데이터 출처 이미지를
   섞는다. 단순 숫자 임시 파일명을 Pixiv 글 번호로 추측하지 않는다.
3. `이미지 첨부`로 한 번에 선택한다. 파일 선택 순서를 기록하고 사이트가
   완료한 이미지 순서와 각 이미지 아래 출처를 비교한다.
4. 파일 크기를 다르게 한 사례도 반복한다. 파일명·메타데이터가 확인된
   이미지에만 해당 출처가 붙어야 한다. 사이트의 이미지 순서를 확장이
   강제로 재정렬했다고 해석하지 않는다.
5. 같은 파일명/크기/수정 시각을 가지지만 출처가 다른 이미지: 자동 기재
   없이 안내가 나와야 한다. 기존 파일과 새 파일이 같은 이름이면서 다른
   출처인 경우도 동일하다.
6. 같은 이미지를 중복 첨부한 경우 모든 가능한 출처가 같으면 각 이미지에
   한 번씩 기재할 수 있다. 어느 중복 파일이 먼저 끝났는지는 확정하지 않는다.
7. 파일명 속성이 없거나 충돌하는 이미지, 출처가 없는 이미지, 실패한 이미지:
   다른 이미지의 출처를 가져오거나 본문 끝에 캡션을 추가하면 안 된다.
8. native 업로드 실패/재시도를 시험한다. blob/data 미리보기 단계에는 출처가
   붙지 않아야 하며, 최종 루리웹 이미지 URL의 디코딩 성공 후 한 번만 붙는다.
9. 기존 본문 텍스트, 수정 화면의 기존 이미지, 커서/포커스와 사용자 작성
   캡션이 보존되는지 확인한다. 혼합 텍스트/여러 이미지가 한 문단에 있으면
   자동 기재하지 않는 보수적 제한을 확인한다.
10. 키보드, 터치 스크롤, 화면 회전, 좁은 화면 및 라이트/다크에서 버튼·모달을
    확인한다. 댓글/답글의 아이콘·기존 출처 버튼도 회귀 확인한다.

## 데스크톱 Firefox 및 Whale

- 각각 `firefox/`, `whale/`를 별도의 개발 프로필에서 로드한다. 기존 설치본을
  제거하거나 설정을 초기화하지 않는다.
- `bbs.ruliweb.com`의 신규 작성/수정 화면에서 위 3~9를 반복한다.
- 에디터2의 기존 `.icon-camera` 버튼과 연결 파일 입력이 유지되는지 확인한다.
  라벨은 `이미지 첨부`이고 한 번 누르면 기본 파일 선택기를 한 번 열어야 한다.
- 사이트에서 비활성화한 업로드 버튼은 비활성 상태를 유지해야 한다.
- 아이콘 선택/태그/통합 버튼과 세 모달에 동일한 기존 캐릭터가 나와야 한다.
  텍스트와 닫기 버튼이 겹치지 않고 이미지 오류 시 대체 SVG가 나와야 한다.
- NORMAL/BUNDLE, 100개 이미지·MP4 태그, 검색/필터, 더블클릭 삽입,
  일괄 다운로드 및 기존 Native Host/메타데이터 기능을 수동 회귀 확인한다.

## 읽기 전용 진단

시험 업로드를 완료한 뒤 `READONLY-UPLOAD-DIAGNOSTIC.js` 전체를 해당 페이지
Console에서 실행하고 출력 JSON만 전달할 수 있다. 파일명·출처 URL·본문·쿠키·
인증 정보는 수집하지 않는다. 요청이나 작성기 상태를 변경하지 않는다.
Android Console 접근에는 Firefox 원격 디버깅이 필요할 수 있다.

`extension.events`는 파일 선택, 메타데이터 처리 완료, 에디터 이미지 발견,
확인된 캡션 삽입 순서다. `editorOrder`의 `selectionIndex`는 **확인된 유일한
파일명 대응에만** 존재한다. 중복 출처 동등성은 파일 순서를 추측하지 않는다.
업로드 HTTP 요청/응답 페이로드를 감시하거나 가로채는 기능이 아니다.

Performance의 업로드 관련 타이밍이 있으면 별도 시작/완료 순서를 보여주지만
브라우저의 버퍼·타이밍 제한으로 누락될 수 있다. 타이밍을 특정 파일과
연결했다고 주장하지 않는다. 실제 요청·콜백 원인 확정에는 사용자 기기의
Network 순서와 사이트 API 확인이 필요하다.

진단 데이터가 없으면 현재 페이지에 새 개발본이 주입됐는지와 버전을 먼저
확인한다. 이 경우를 출처 매칭 성공 또는 사이트 순서 문제로 단정하지 않는다.
