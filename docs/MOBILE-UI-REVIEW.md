# Android Firefox 선택기 UI 소스 감사

기준: 공개 RC3 / 0.1.2, 최초 공개 커밋 `1164afc3745d6af47e4e3fc750540963226f8355`.
작성일: 2026-10-13. 이 문서는 수정 전 소스에 대한 독립 읽기 전용 감사이다. 변경된 모바일 UI의 시험 결과는 별도의 검증 보고서를 기준으로 한다.

Impeccable 4.3.1의 기술 감사 기준(접근성, 반응형, 성능, 테마, 구현 일관성)을 참고했다. 세션의 context 및 adapt 실행은 주 작업에서 수행했다. 여기서는 소스에서 확인할 수 있는 사항만 기록하며, Android 기기 화면이나 설치된 확장의 실사용 결과를 평가한 것으로 표시하지 않는다. 측정하지 않은 WCAG 적합률·렌더링 속도·디코딩 성공률을 수치화하지 않는다.

## 태그 필터에서 확인한 사실

- `renderChips(true)`는 검색 엔진이 연결되면 `libraryFixedTags`의 고정 13개를 팩의 메타데이터 유무와 관계없이 표시한다. 따라서 칩이 보인다는 것만으로 원본 태그 수집·검색 인덱스 연결이 성공했다고 판단할 수 없다.
- 검색 엔진이 연결되지 않은 경로는 `pack.tags` 사전을 사용한다. 자유 태그를 고정 칩으로 임의 생성하지 않는다.
- `library-search.js`의 태그 필터는 정규화된 실제 저장 태그와 완전 일치한다. 텍스트 검색은 태그 부분 일치와 게시글 제목도 비교한다. `아루`만 저장된 아이콘이 `미소` 고정 필터에서 제외되는 것은 정책상 정상이다.
- 칩은 일반 `click`으로 조건을 갱신하며 터치 이벤트를 일괄 차단하는 코드는 없다. `aria-pressed`도 갱신한다. Android의 실제 원본 태그 전달, 확장 초기화, 저장된 캐시 및 이벤트 발생은 이 소스만으로 성공 또는 실패를 확정할 수 없다.
- 검색 조건을 바꿀 때 팩을 다시 요청하지 않고 현재 모델을 필터링한다. 새 모바일 UI에서도 고정 태그 OR/AND, 텍스트와 태그의 AND 결합, 자유 태그 검색은 유지해야 한다.

## 기존 안전장치와 유지할 동작

- Shadow DOM으로 사이트 CSS와 UI를 분리한다.
- Wine/Champagne 토큰, Pretendard의 로컬 FontFace, 사이트 실제 배경 기반 테마 감지를 사용한다.
- `role=dialog`, `aria-modal`, 입력 레이블, 라이브 상태 안내, 표시·숨김·inert를 고려한 Tab 순환이 있다.
- 팩 목록을 열면 뒤쪽 그리드·미리보기·상태 영역을 inert로 만든다. 팩 목록이 열린 상태의 선택·삽입도 코드에서 차단한다.
- 터치 이동 8px 초과와 pointercancel을 카드 선택에서 제외한다. 더블클릭 삽입에는 실제 마우스 pointer 증거와 trusted 이벤트가 필요하다. 모바일 합성 더블클릭으로 삽입하지 않는다.
- 작은 화면에서 미리보기는 64/82px 이미지와 삽입 버튼이 있는 간결한 배치가 이미 있다. 높이가 짧을 때 이를 `display:block`으로 다시 펼치는 CSS가 병목이다.
- 화면 설정 저장 키는 캐시·태그·즐겨찾기와 별도이며 저장 실패에도 기본 UI를 유지한다.
- 닫을 때 이벤트·옵저버·미디어·프레임·검색 작업을 정리하고 원래 실행 버튼에 초점을 복원한다.

## 1,548개 가상 스크롤의 소스상 비용

- `MAX_CARDS=72`; 논리 결과가 1,548개여도 모든 카드를 한꺼번에 DOM으로 만들지 않는다.
- scroll 갱신은 requestAnimationFrame당 최대 한 번이다. 보이는 행과 양쪽 여분 한 행을 계산한다.
- 열 수는 2–8이며 viewport·아이콘 크기·카드 예산으로 결정한다. 크기 변경 시 기존 첫 논리 아이콘과 행 내 비율을 기준으로 스크롤 위치를 다시 계산한다.
- 겹치는 카드 재사용 조건은 아이콘 ID·인덱스·열 수·행 높이의 일치다. 다른 아이콘에 기존 이미지/태그 DOM을 재바인딩하지 않는다.
- 미디어 요청은 `MediaBudget(4)`와 viewport 가시성 조건으로 제한한다. 그리드의 `loading=eager`만 보고 전체 1,548개를 요청한다고 판단하면 안 된다.
- `renderGroups()`는 검색 조건 갱신 시 그리드를 재생성하고 미디어 예산·옵저버를 초기화한다. 전체 팩 수집 진행 중 `applySearch(false)`도 이를 수행한다. 새 로딩 애니메이션에서 진행 횟수만 바뀌어도 `renderGroups()`를 부르는 구조를 추가하면 안 된다.
- 수집·정규화·검색 인덱스 비용은 전체 모델 크기에 비례할 수 있다. 72개 DOM 한도는 전체 처리 시간을 보장하지 않는다. 네트워크·디코딩 및 실제 Android 프레임 시간은 별도 측정 대상으로 남긴다.

## 로딩 UI 연결 검토

`setProgress(info)` / `paintProgress(info)`는 실제 수집 상태를 받는 기존 경계다. loaded와 total이 확인됐을 때만 수치를 표시하고, total이 없을 때는 전체 미확인을 표시한다. 전체 팩 검색 진행의 cached/loaded/failed 수치는 **팩 개수**이며 아이콘 개수로 표시하면 안 된다. 기존 정상 팩은 새 팩 수집 완료 전에 파괴하지 않는다.

권장 사항:

1. 모달·팩 요청별 토큰을 유지하며 늦게 끝난 응답이 현재 팩의 로딩/오류를 덮어쓰지 않게 한다.
2. 진행 텍스트와 애니메이션 상태만 바뀔 때는 그리드/미디어를 재생성하지 않는다.
3. 실패·일부 실패·사용자 취소·성공을 구분한다. 검색 결과 없음과 수집 전 빈 상태도 구분한다.
4. 애니메이션은 pointer-events:none인 장식이며, 상태 텍스트가 접근 가능한 정보를 제공한다. reduced-motion에서는 정지된 에셋과 실제 상태 문구를 유지한다.
5. 검색·닫기·취소를 애니메이션으로 가리지 않는다. 라이브 안내를 프레임마다 반복하지 않는다.

## 공개용 그래픽과 라이선스

`THIRD_PARTY_NOTICES.md`는 공개 그래픽이 `tools/create-placeholders.mjs`에서 외부 입력 없이 생성된 기하학 PNG임을 명시한다. 공개 소스에는 재배포 허락이 확인되지 않은 Aru 캐릭터 시트·분리본·아이콘팩 미디어를 넣지 않았다.

현재 `DesignSystem.modalHeader()`와 확장 Manifest는 로컬 `assets/icons/modal-select-256.png`, `modal-bundle-256.png`, `modal-tags-256.png`를 사용한다. 이 경로의 **공개 파일은 캐릭터 그림이 아니라 공개용 대체 그래픽**이다. 파일 이름만 보고 원래 캐릭터 에셋을 가져오면 안 된다.

이번 개발에서 CSS 애니메이션에 기존 공개용 A/선택 기하학 에셋을 재사용하는 것은 현재 공개 정책과 일치한다. 캐릭터 그림을 공개 패키지에 포함하려면 별도의 재배포 권한 확인이 필요하다. 기존 설치본의 비공개 그림을 자동 복사하거나 다운로드하지 않는다. 외부 CDN·원격 폰트·원격 애니메이션 의존성도 추가하지 않는다.

## 검증 제안과 실기기 구분

자동화에서는 coarse pointer·좁은 창·visualViewport 모형으로 다음을 확인할 수 있다. 이는 Android Firefox 설치본 검증이 아니다.

- 최초 열기, 팩 선택 성공, 목록 재열기에서 편집 가능한 요소가 자동 초점이 되지 않는지; 데스크톱 초점은 유지되는지.
- 상세 조건 접기/펼치기·고정 태그 가로 탐색 후 실제 결과 수와 aria-pressed를 확인하는지.
- visualViewport 높이/폭 변경 후 그리드 행·열·카드 인덱스와 72개 상한을 유지하는지.
- 1,548개 목록 처음/중간/끝의 미디어·태그가 맞는지; 검색·아이콘 크기 변경 중 선택 ID가 유지되는지.
- pointermove/pointercancel 후 click/dblclick이 아이콘 삽입을 발생시키지 않는지.
- 수집 취소/팩 전환/닫기 후 늦은 응답·프레임·미디어가 UI를 변경하지 않는지.
- 로딩/실패/재시도 상태에서 수치 단위가 정확하며 실제 수집된 태그가 계속 검색되는지.
- 공개 브라우저 폴더에 비공개 캐릭터 이미지가 새로 생기지 않았는지; 기존 로컬 에셋·FontFace만 사용하는지.

스크린샷은 데스크톱 라이트/다크와 360px 또는 390px 폭의 모바일 모형을 함께 캡처한다. 모형에서 키보드와 같은 viewport 축소를 재현하더라도 실제 Android 키보드로 표시하지 않는다.

Android Firefox 사용자 수동 검증에서는 설치 버전, 팩 글 번호, 화면 방향, 성공/실패 단계만 기록한다. 댓글 내용·작성기 본문·로그인/인증·storage 원문은 공유하지 않는다. 최초 키보드, 직접 탭 입력, 주소창 접힘/펼침, 회전, 키보드 닫기, 칩 가로 스와이프, 페이지 본문 스크롤 보존, 실제 태그 검색·필터, MP4 미리보기, 명시적 삽입을 확인한다. 게시글/댓글 등록 버튼은 누르지 않는다.

실제 Android Firefox 접근 및 설치 확장 검증: **사용자 수동 검증 필요**. 이 감사는 원래 소스의 문제와 기존 안전장치를 확인했으며 수정 완료나 실제 브라우저 회귀 통과를 대신하지 않는다.
