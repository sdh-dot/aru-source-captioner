# 이미지 업로드·출처 매칭 및 UI 수정 결과

2026-10-15. 개발 브랜치 `fix/android-upload-attribution`.
기준 커밋 `a6087a7c740db200f1aba6c3941ec9c8338501f4`의 모바일 로딩 UX를 포함한다.
Firefox **1.0.4**, Whale·Chromium **0.1.3**. 안정본·스토어 제출 ZIP·GitHub main은 변경하지 않는다.

## 원인과 확인 범위

| 항목 | 실제 소스에서 확인한 사실 | 실환경에서 확인하지 못한 사항 |
|---|---|---|
| 이미지 순서 | 사이트의 기본 업로드를 관찰하며 확장이 업로드를 직렬화하지 않았다. | Android 파일 선택기 순서, 사이트 요청·콜백·삽입 순서가 달라지는 정확한 원인. |
| 잘못된 출처 대응 | Firefox 모바일 경로에 첫 미처리 이미지에 삽입하는 FIFO와 시간 초과 시 본문 끝에 추가하는 경로가 있었다. 파일명·크기·수정 시각에 따른 중복 생략도 있었다. | 사용자가 보고한 각 이미지가 어느 경로를 거쳤는지. 기기 로그를 확보하지 않았다. |
| 처리 시점 | 메타데이터를 비동기로 읽은 뒤 기록하므로 먼저 등장한 이미지의 DOM 이벤트를 놓칠 수 있었다. 같은 이름의 출처는 FIFO로 소비했다. | 사이트가 파일별 업로드 식별자를 제공하는지. |
| 캐릭터 차이 | 공개 준비본에는 캐릭터 대신 기하학 PNG가 있었다. 버튼·헤더는 브라우저 내부 에셋 URL을 사용한다. | 설치된 모바일 1.0.3의 정확한 파일 해시·캐시 상태. |

확장 측 위험 경로를 제거하고 완료 순서에 의존하지 않는 매칭으로 교체했다.
사이트 업로더의 요청·완료·이미지 삽입 순서를 강제로 변경하지 않는다.
실제 순서 안정화는 사이트의 파일별 API 및 Android 관찰 자료 없이 완료했다고 보고할 수 없다.

## 파일별 대응 및 삽입

- 모든 선택 파일을 먼저 세션에 등록한 뒤 최대 2개씩 기존 파일명·EXIF/XMP/IPTC·PNG 파서로 읽는다.
- 파일에 세션 ID·배치 ID·선택 인덱스를 부여한다. 이는 진단용 식별자이며 서버 응답과 연결된 업로드 ID라고 주장하지 않는다.
- 해당 작성기에서 새로 등장한 이미지의 `alt`·`title`·`data-original-name`·`data-filename`과 정확한 파일명을 비교한다. 이미지가 먼저 나타나도 메타데이터 완료 후 다시 판단한다.
- 대응 후보와 같은 이름의 이전 처리 이력까지 확인한다. 출처가 다르거나 누락·처리 중이면 순서로 추측하지 않는다. 모든 후보 출처가 같을 때만 중복 첨부에 같은 출처를 기재할 수 있다.
- 이미지 URL은 파일 매칭에 사용하지 않는다. 최종 루리웹 이미지 호스트의 HTTPS URL과 디코딩 성공은 업로드 준비 여부에만 사용한다. blob/data 미리보기·디코딩 오류에는 기재하지 않는다.
- 기존 캡션·기존 이미지·텍스트를 포함한 혼합 문단은 건드리지 않는다. 삽입 성공 후에만 해당 대응을 소비해 재시도·중복 이벤트로 같은 이미지에 두 번 기재되지 않게 한다.
- 대응이 불명확하면 안내하고 자동 기재하지 않는다. 5분이 지난 이름은 세션 내 격리하며 512개 세션 기록 한도 도달 시 이후 자동 기재를 중단하고 안내한다.
- 기존 HTML 출처 생성·URL 허용 정책·댓글 출처 기능·다운로드·Native Host 코드는 유지한다. 네이티브 업로드와 선택 파일을 재구성하지 않는다. Whale의 기존 선택적 픽셀 테이블 기능도 유지한다.

메타데이터가 없는 파일, 파일명 속성을 제공하지 않는 작성기, 여러 작성기의 대응을 구분할 수 없는 경우에는 수동 기재가 필요하다. 자동 순서 추측으로 해결하지 않는다.

## UI 및 에셋

- 기존 `.icon-camera` 버튼과 이미지 파일 입력에 연결된 라벨만 장식한다. 기존 노드·이벤트·비활성 상태·파일 선택 동작은 보존한다.
- 캐릭터와 `이미지 첨부` 문구는 클릭을 가로채지 않는 레이어이며 최소 높이는 44px이다. 라벨 없는 기본 파일 입력은 OS 버튼을 보존한다.
- 아이콘 선택·태그·통합과 세 모달에 RC3의 동일한 캐릭터 PNG를 두 브라우저 모두 적용했다. 이미지 첨부에는 기존 사진 프레임 캐릭터를 재사용했다.
- 헤더 캐릭터는 데스크톱 128px, 좁은 화면 56px, 짧은 화면 32px이다. 원본 256px PNG를 사용한다. 로딩 실패 시 작은 장식 SVG를 제목 옆에 표시해 빈 캐릭터 열을 남기지 않는다.
- 라이트·다크 토큰, 로컬 Pretendard, 검색/필터·가상 스크롤·모바일 로딩 UX는 유지한다.
- 공개 재배포는 소유자가 2026-10-15 확인했다. 캐릭터에 MIT를 적용하지 않는다. [권리 고지](CHARACTER-ASSETS-NOTICE.md)와 [파일 출처·해시](CHARACTER-ASSET-PROVENANCE.json)를 분리한다.

## 실환경 및 배포 판단

Android Firefox 기기에 연결하지 못했고 실제 업로드·작성기·마켓 설치 검증은 미완료다. 데스크톱 Firefox도 실환경 검증하지 않았다.
Whale은 새로 조회한 창 ID로 한 번 접근했으나 도구의 창 소유자 검증 오류가 동일하게 발생해 접근을 중단했다. URL 검사 이전의 접근 오류로, 확장 결함으로 분류하지 않는다. 다른 브라우저 결과를 Whale 검증으로 보고하지 않는다.

두 브라우저 테스트 ZIP과 소스는 개발·검토용이다. 스토어 서명·제출·설치 교체·main 병합은 하지 않는다. 정식 배포 판단에는 [수동 검증 절차](UPLOAD-MANUAL-TESTING.md)의 Android/Firefox/Whale 업로드 및 기존 기능 확인이 필요하다. Native Host 실환경도 미검증이다.
