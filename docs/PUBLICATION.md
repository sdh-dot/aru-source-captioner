# 공개 범위와 협업 설정

2026-10-12 소유자가 조건부 최종 승인한 공개 범위입니다. 자체 소스에 MIT를 적용하고, 최종 검사 통과 후 최초 공개를 진행합니다. 실제 GitHub 설정 적용 상태는 완료 보고에서 별도로 확인합니다.

## 공개 대상

Design Polish RC3 / Manifest 0.1.2에서 작성 소스·브라우저별 전체 확장·원문 테스트 코드·최소 공개 검색 사실·합성 데이터·필요한 라이선스·문서·빌드/검사 도구를 포함합니다. GitHub 계정은 `sdh-dot`, 예정 이름은 `aru-source-captioner`, 브랜치는 `main`입니다.

권한이 불명확한 캐릭터 시트·분리본·버튼/헤더/확장 캐릭터 PNG, 실제 아이콘팩 파일·상태 덤프·실사용 화면, 과거 버전·ZIP·백업·로그·캐시·브라우저 프로필·Native Host 실행 파일·개인 환경 설정을 포함하지 않습니다. 공개용 PNG는 원본 자료 없이 코드로 만든 기하학 플레이스홀더입니다. 공개 게시글 URL 참조와 소량의 공개 검색 구조 사실을 이미지 파일의 재배포와 구분합니다.

원본 프로젝트는 다른 프로그램도 포함하는 상위 Git 저장소의 일부입니다. 331개 커밋과 기존 수정 파일을 보존하고, 별도의 검증된 `main` 스냅샷만 새 최초 공개 commit으로 배포하도록 승인받았습니다. 원본 Git 이력의 개인 이메일·다른 프로그램·비공개 환경 기록을 무단 공개하거나 rewrite하지 않습니다. 이력 이전이 필요하면 프로젝트 경로 추출·작성자 정보·과거 blob 검토와 별도 승인이 필요합니다.

## 보안 검사

원본 프로젝트 6,552개 파일, ZIP 내부 6,584개 항목을 읽고 중복 텍스트를 SHA-256으로 묶어 검사했습니다. Git의 모든 reachable ref에서 browser-extension 경로의 93개 blob과 331개 commit 메타데이터를 검사했습니다. 실제 키·토큰·암호를 나타내는 패턴은 발견되지 않았습니다. 인증 URL 형식은 부정 입력 테스트와 그 테스트 로그로 확인했습니다. 이력과 문서에는 이메일·로컬 경로가 있어 원문 감사 자료를 공개 트리에 포함하지 않습니다.

공개 트리의 검출 항목은 Firefox 확장 식별자, 공개 패키지 저작권/유지보수 주소, 합성 `user:pass` 부정 테스트, 로컬 UI demo의 loopback 주소, 코드의 속성 이름 및 픽시브 `/users/` 경로 설명입니다. 개인 로그인·세션·원본 인증 파일을 수집하지 않았습니다. 공개 Git에는 npm 로그·검사 원문·비밀 파일을 넣지 않습니다.

패턴 검사는 모든 비밀의 부재를 보장하지 않습니다. 이미지·실행 파일을 OCR/역분석하지 않았고, 삭제되어 reachable ref에 없는 Git 객체는 검사 범위가 아닙니다. 해당 자료와 원본 이력을 공개 대상에서 제외합니다.

## 라이선스 후보

소유자 승인에 따라 자체 소스·문서·기하학 그래픽에 MIT를 적용하고 LICENSE와 package.json/README에 명시했습니다. exifr MIT와 Pretendard OFL은 별도 고지와 조건을 유지합니다. [제3자 고지](../THIRD_PARTY_NOTICES.md)를 참조하세요. 제공 사실만으로 캐릭터 사용 허락을 추정하지 않습니다.

## 승인 후 GitHub 설정

- Public 저장소 생성 전 이름 중복을 다시 확인합니다. 발견되면 중복 생성·덮어쓰기를 하지 않습니다.
- Issues·PR·Discussions를 사용하고 Issue/PR 템플릿과 CODEOWNERS를 등록합니다.
- `main`은 PR을 요구하고 `build-and-test` 통과 및 대화 해결을 요구합니다. 관리자에게도 적용하고 force push·삭제를 허용하지 않습니다.
- 최초에는 유지보수자가 소유자 한 명이므로 필수 승인 리뷰 수는 0으로 계획합니다. PR은 필요하며 병합 권한은 소유자/승인된 쓰기 권한자에게만 있습니다. Collaborator가 승인되면 리뷰 1개 요구를 검토합니다.
- 임의로 Collaborator를 초대하거나 일반 방문자에게 쓰기 권한을 주지 않습니다. 방문자는 Fork와 PR을 사용할 수 있습니다.
- GitHub Private vulnerability reporting과 지원되는 보안 기능을 활성화하고 실제 상태를 확인합니다.
- 개인 계정의 지정 push 사용자 제한과 계정별 보호 기능은 제공 범위에 따라 다릅니다. API 거절 또는 미지원이면 우회하지 않고 보고합니다.

위 설정은 적용 결과가 아닙니다. 저장소 생성과 최초 Push 후 실제 값을 읽고 보고해야 합니다.
