# Android Firefox 태그 검색·필터 조사

사용자가 확인한 실패는 작성기의 **아이콘 태그 편집기**가 아니라 아이콘 선택기의 **태그 검색·필터**다. 이 문서는 선택기 데이터 흐름과 이번 자동화에서 확인할 수 있는 범위를 기록한다.

## 확인한 코드와 조건

| 단계 | 소스 | 확인한 동작 / 실패 조건 |
|---|---|---|
| 원본 속성 | `docs/source/ruliweb-icons/site-adapter.js`의 `imageAttributes`, `readArticlePack` | IMG와 VIDEO 모두의 `data-aru-id`, `data-aru-tags`를 읽는다. 속성 없음은 빈 태그이며, 디코딩 오류는 `tagError`/진단 수치로 남긴다. 이미지 URL 수집 성공과 태그 수집 성공은 별개다. |
| BUNDLE 참조 | 같은 파일의 `verifyReferences` | 확인한 원본 URL의 유일한 미디어 요소에서 태그를 연결한다. 동일 URL에 여러 태그 소유자가 있으면 임의로 하나를 고르지 않는다. BUNDLE 본문 자체에는 개별 태그가 없는 것이 정상일 수 있다. |
| 코덱 | `attribute-tags.js` | 기존 `aru-tags:v1:` URL 인코딩 JSON 배열 규격을 유지한다. 고정 태그와 자유 태그에 별도 모바일 규격은 없다. 쉼표가 포함된 자유 태그는 v1에서 태그 한 개다. |
| 검색 색인 | `library-search.js`의 `tags`, `rebuild`, `search` | `imageMetadata.tags`와 `tagIds` 사전 이름을 정규화한다. 선택한 고정 태그는 정확히 일치해야 한다. 텍스트는 태그·게시글 제목에서 AND/OR로 검색한다. 추론 태그를 생성하지 않는다. |
| 필터 이벤트 | `picker.js`의 `renderChips`, `applySearch` | 칩은 표준 button/click 이벤트를 사용한다. 터치에서 발생한 클릭도 같은 경로를 따른다. 태그 선택은 검색 엔진의 `selectedTags`로 전달되며 원본 재조회가 필요 없다. |
| 한글 입력 | `picker.js`의 composition/input 리스너 | 조합 종료 후 검색한다. 디바운스 전에 칩을 누르면 확정된 현재 입력값을 함께 반영한다. |
| 상태 보존 | `picker.js`의 `setPack` | 새 원본을 반영할 때 검색어·태그 조건을 유지하고 화면 결과를 다시 계산한다. |

태그 검색 엔진에는 Android에서 다른 API를 호출하는 분기가 없다. 태그 데이터는 원본 공개 속성과 팩 모델에서 읽으며 필터 클릭이 storage를 읽거나 쓰지 않는다. Mozilla는 Android Firefox의 `storage.sync`가 계정과 동기화되지 않는다고 설명한다. 이것만으로 선택기 태그 실패의 원인으로 판단할 수 없다. [Mozilla storage.sync 문서](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage/sync)

## 실제 원인으로 확정하지 않은 항목

- Android Firefox 실제 저장 DOM/응답에서 태그 속성이 유지되는지
- 실패한 팩의 캐시 모델에 태그가 있는지
- BUNDLE의 모든 참조가 조회·URL 확인·태그 연결까지 완료됐는지
- 모바일 화면에서 입력 키보드/필터 영역이 조작을 막았는지
- 실제 Android 한글 키보드가 보낸 이벤트 순서

같은 합성 데이터를 기준으로 기존 RC3와 이번 개발본 모두에서 아래 6개 회귀 테스트가 통과했다. 따라서 검색 엔진 자체가 모바일에서 실패한다고 재현되었다고 보고하거나, 근거 없이 코덱·검색 조건을 변경하지 않았다. 모바일 레이아웃·포커스 변경은 별도로 검증한다. 실제 실패 원인을 좁히려면 아래 읽기 전용 진단 결과가 필요하다.

## 자동화 결과

명령: `node --test tests/mobile-tags.test.cjs`

| 항목 | 기존 RC3 | 개발본 |
|---|---:|---:|
| m/bbs URL에서 97 IMG + 3 MP4의 100개 태그 수집·색인 | 통과 | 통과 |
| 터치 출처 클릭, 고정 태그 OR/AND, 필터 중 네트워크 요청 없음 | 통과 | 통과 |
| 한글 조합 종료, 디바운스 전 칩 클릭 | 통과 | 통과 |
| 일부 속성 누락 / 잘못된 인코딩과 미디어 로딩 분리 | 통과 | 통과 |
| 새 태그 재색인, 검색 조건 유지, 화면 표시 갱신 | 통과 | 통과 |
| 진단 코드가 DOM·설정·인증을 변경/수집하지 않음 | 통과 | 통과 |

각 실행: **6개 통과, 실패 0개**. Node/jsdom의 360px/coarse-pointer 합성 환경이다. Android Firefox 설치 확장, 터치 드라이버, 실제 키보드, 브라우저 네트워크 및 저장소를 검증한 결과가 아니다. 기존 96개 역사 회귀 실패 및 9개 Mozilla 경고와는 별도의 신규 테스트다.

기존 RC3 비교는 `ARU_TAGS_SOURCE_ROOT`를 보존된 공개 스냅샷 폴더로 지정하여 같은 테스트·기대값을 실행했다. 기본 실행은 현재 개발 소스를 사용한다.

## Android Firefox 수동 확인 및 읽기 전용 진단

1. 태그가 저장된 **원본 NORMAL 게시글**에서 선택기를 열고 아이콘이 표시된 뒤 `아루`를 검색한다. 키보드를 닫고 고정 태그 칩이 보이는지 확인한다.
2. `미소`/`분노`를 각각 선택·해제하고 눌림 표시와 결과 개수가 바뀌는지 확인한다. 실제 태그가 없는 게시글에서 특정 결과 수를 기대하지 않는다.
3. 태그 OR/AND를 바꾸고 텍스트 조건과 동시에 적용되는지 확인한다. 자유 태그도 검색한다.
4. BUNDLE에서는 원본을 읽는 동안과 읽은 뒤의 상태를 구분한다. 원본 새로고침 후 변경된 태그가 반영되는지 확인한다.
5. 작성기의 아이콘 태그 편집기는 별도 회귀 항목이다. 기존 본문을 자동 등록하지 않고 이미지 선택·태그 추가·제거·명시적 적용·실행 취소를 확인한다. 실제 모바일 편집기의 지원 API는 미검증이다.
6. 데스크톱 Firefox의 Android 원격 디버깅 등 접근 가능한 Console의 **페이지 컨텍스트(top)**에서 `docs/MOBILE-TAGS-READONLY.js` 전체를 실행한다. 출력 JSON만 전달한다. [Mozilla 원격 디버깅 안내](https://firefox-source-docs.mozilla.org/devtools-user/remote_debugging/index.html)

진단 코드는 네트워크 요청, storage, 쿠키, 인증 정보, 댓글, 에디터 내용에 접근하지 않으며 DOM을 변경하지 않는다. 공개 본문의 미디어 속성 **개수·디코딩 실패 위치**와 선택기 **버튼 눌림·비활성화 상태·화면 카드 개수**만 읽는다. 검색어의 실제 문자열은 수집하지 않는다. 원본 태그 진단은 해당 NORMAL 글에서 실행한다. BUNDLE에 개별 태그 속성이 없다는 결과를 원본 태그 누락으로 해석하지 않는다.

현재 실제 Android Firefox 결과: **사용자 수동 검증 필요**. 동일 증상이 계속되면 원본 NORMAL 글에서의 JSON과 실패한 팩 글 번호, 태그를 눌렀을 때 눌림 표시가 바뀌는지 여부로 다음 조사 범위를 정한다.
