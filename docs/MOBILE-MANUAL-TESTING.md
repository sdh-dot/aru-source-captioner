# 모바일 개발본 수동 검증

기준: RC3 / 0.1.2. 이번 빌드는 별도 브랜치이며 미서명 개발 패키지다. 기존 설치본, 제출 ZIP, 설정, 태그, 로그인, 작성 중인 내용을 자동 변경하지 않았다.

## 로드 경로

- Firefox: 저장소 루트 기준 `firefox/manifest.json`
- Chrome/Edge/Whale: 저장소 루트 기준 `whale/`
- 패키지: 같은 작업 트리의 `dist/firefox/`, `dist/whale/`. 서명된 Android 배포본이 아니다.

PC Firefox는 별도 테스트 프로필에서 `about:debugging#/runtime/this-firefox`의 임시 부가 기능 로드로 Manifest를 선택한다. Chromium은 별도 테스트 프로필의 확장 개발자 모드에서 압축해제 폴더를 로드한다. 실제 설치본을 교체하는 작업은 사용자가 선택해 수행한다.

Android는 PC의 임시 로드 방식과 다르다. Mozilla의 [Firefox Android 개발 안내](https://extensionworkshop.com/documentation/develop/developing-extensions-for-firefox-for-android/)에 따라 ADB와 web-ext로 테스트할 수 있다. 안내는 Android 임시 로드가 주 프로필을 사용한다고 명시한다. 기존 설치본과 같은 ID이므로 일반 사용 기기에서 바로 실행하지 말고 별도 테스트 기기/에뮬레이터를 사용한다. 이 작업에서 USB 디버깅 설정, ADB 연결, 소프트웨어 설치, 확장 교체는 수행하지 않았다.

필요한 환경을 사용자가 준비한 뒤 개발 확장 폴더에서 다음을 실행할 수 있다. `web-ext`는 이번 package.json에 새로 추가하지 않았고 명령 자체는 이 환경에서 실행하지 않았다.

```text
web-ext run -t firefox-android --source-dir firefox
```

기기와 Firefox 패키지는 실제 설치 환경에 맞게 선택한다. Android 최소 버전은 기존 Manifest의 142.0을 유지한다. 이 값을 유지한 사실이 모든 API를 실기기로 검증했다는 뜻은 아니다.

## UI와 기능

1. 빈 댓글 작성기에서 아이콘 선택을 연다. 최초·재진입·목록 재열기·팩 선택 성공 후 가상 키보드가 자동 표시되지 않아야 한다.
2. 검색창을 직접 누르면 키보드가 나타나야 한다. 한글 `아루`를 조합하여 입력하고, 키보드를 유지한 채 목록을 스크롤·선택한다.
3. 일반 모바일 높이에서는 태그를 가로 스크롤한다. `검색·화면 설정`에서 현재/전체 팩, 텍스트/태그 AND/OR, 화면 크기, 아이콘 크기, 미리보기를 조절한다.
4. 키보드/가로 화면 등 높이가 작은 경우 검색창 옆 `필터`를 열어 태그와 설정에 접근한다. 닫으면 그리드가 남고 삽입 버튼이 화면 내부에 있어야 한다.
5. 5044를 고른다. 실제 단계/처리량, 중지, 다시 선택, 닫기, 재시도를 확인한다. 확인되지 않은 URL 경고가 있다면 개수와 진단을 보존한다. 1,548개 4998에도 반복한다.
6. 같은 팩 연속 탭은 중복 요청을 만들지 않아야 한다. 다른 팩 또는 닫기 이후 이전 데이터가 목록을 덮어쓰지 않아야 한다. 실패 후 이전 정상 팩이 유지되어야 한다.
7. 태그가 보이는/보이지 않는 아이콘을 비교한다. 원본 NORMAL 글에서 저장 태그를 확인한 뒤 `새로고침`으로 해당 팩만 다시 읽는다. 태그 없는 기존 아이콘에 태그를 임의 생성하면 안 된다.
8. MP4/WEBM과 이미지의 미리보기·실패 안내·재시도를 확인한다. native 삽입 제한이 있는 형식은 기존 정책대로 안내해야 한다.
9. 빈 댓글/답글/게시글 작성·수정에서 선택 후 삽입한다. 다른 작성기에 들어가지 않는지, 원래 텍스트/커서/undo가 유지되는지 확인한다. 실제 등록 버튼은 누르지 않는다.
10. 터치 스크롤은 카드 선택/더블탭 삽입을 일으키면 안 된다. PC 마우스 더블클릭 삽입은 기존 경로를 유지한다.
11. 화면 회전, 주소창 변화, 미리보기 접기, 키보드 닫기, X/ESC/Tab, 라이트/다크, 모션 감소를 확인한다. 모달 종료 후 페이지 스크롤과 초점이 복원되어야 한다.
12. 태그 편집기의 이미지/MP4 태그 추가·수정·삭제와 통합팩 생성·검색, 출처·다운로드·Native Host는 별도 회귀로 확인한다. 실제 게시글 저장은 사용자만 수행한다.

## 태그/3867 읽기 전용 진단

데스크톱 Firefox의 [about:debugging 원격 연결](https://firefox-source-docs.mozilla.org/devtools-user/about_colon_debugging/index.html)로 **실제 Android 탭**의 Console(top)을 선택한다. PC 탭 결과를 Android 결과로 보내지 않는다.

1. 5044 선택기를 로딩 완료/경고 상태에서 연 채 [MOBILE-TAGS-READONLY.js](MOBILE-TAGS-READONLY.js) 전체를 실행한다.
2. 태그가 빠진 아이콘의 원본 NORMAL 게시글에서 같은 진단을 실행한다. 3867과 5039에서 각각 실행하면 원본 태그 누락과 통합팩 연결 누락을 구분할 수 있다.
3. 출력된 JSON만 전달한다. Android/Firefox 버전, 실패한 원본 글 번호, 선택기 태그 표시 유무를 함께 기록한다.

진단은 공개 미디어 속성 개수·디코딩 실패 위치, 보이는 카드/필터 상태, 개발본의 공개 원본 URL 대조 요약만 읽는다. 쿠키, storage, 로그인, 인증, 댓글/에디터 내용, 검색 문자열, 전체 Console 로그를 수집하지 않는다. 네트워크 요청이나 DOM 변경도 없다. 기존 설치본에도 기본 진단은 가능하지만 `sourceChecks`는 새 개발본에서만 제공될 수 있다.

`sourceChecks`의 URL 상태 verified와 metadataStatus는 별개다. BUNDLE 본문에 개별 태그 속성이 없는 것은 정상일 수 있다. 원본에서 data-aru-tags가 존재하는지 확인해야 한다. 원본 DOM에 태그가 없는 경우 선택기에서 추론해 채우지 않는다.

## 성능 기록

실제 기기에서 선택기 실행부터 첫 목록/전체 태그 준비까지 시간을 기록한다. 네트워크 속도, 팩 번호, 캐시 유무, 화면/키보드 상태를 함께 남긴다. 검색만으로 원본 재요청이 생기는지 확인한다. 오류 로그는 공개 글 번호와 오류 코드만 전달하고 인증 헤더나 전체 네트워크 내보내기는 보내지 않는다.

현재 실기기 결과는 모두 **사용자 수동 검증 필요**다.

## 이번 후속 수정 재현

1. 읽을 수 있는 이미지 URL은 정상이고 `data-aru-tags`만 잘못 인코딩된 합성 NORMAL 팩으로 자동 테스트를 실행한다: `node --test tests/loading-reader.test.cjs`.
2. 태그 읽기 실패 후에도 이미지는 남고 완료가 아닌 partial이어야 한다. 전체 팩 검색에서도 부분 상태여야 한다.
3. 같은 원본의 태그가 정상으로 수정된 뒤 다시 읽으면 실제 태그가 검색되고 complete로 바뀌어야 한다. 태그가 애초에 없는 정상 자료는 오류로 분류하지 않는다.
4. 실제 원본을 사용자 허락 없이 수정하지 않는다. 실기기에서는 실패가 있는 본인의 테스트 자료와 정상 자료를 비교한다.

## 기기 준비와 기록 양식

별도 테스트 기기/에뮬레이터에 Firefox를 준비하고 Android USB 디버깅 및 Firefox의 USB 원격 디버깅을 켠다. PC에 Android Platform Tools/ADB와 web-ext가 준비된 상태에서 `adb devices`로 기기를 확인하고 위 web-ext 명령을 실행한다. 필요하면 `--adb-device` 및 `--firefox-apk`로 실제 대상을 지정한다. Android 임시 로드는 주 프로필에 들어가므로 기존 설치와 같은 ID를 가진 개발본으로 일반 사용 프로필을 교체하지 않는다. 절차 근거: [Mozilla 개발 안내](https://extensionworkshop.com/documentation/develop/developing-extensions-for-firefox-for-android/).
